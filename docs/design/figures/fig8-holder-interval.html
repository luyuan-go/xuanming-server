关键：COUNT 和 INSERT 是同一段临界区，锁从头持有到 COMMIT。T2 只能等 T1 整个临界区结束才拿锁 → 它的 COUNT 必然看到 T1 提交后的最新值。

等 player(B) 锁…
T1 提交后才拿到锁 → COUNT 200 → 拒绝 B→C
B=200 停住
T2 的 COUNT 起点（绿框左端）被挡在 T1 的 COMMIT（t2）之后。T2 看到的永远是 T1 提交后的 200，绝无可能和 T1 同时看到 199。所以 B 的好友数最多停在 200 = 上限（"满"，不是"超"），不会到 201。
