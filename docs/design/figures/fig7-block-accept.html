场景：TA = 接受 A→B，TB = B 拉黑 A，几乎同时提交。（无 pair 守卫时的交错 —— pair 守卫存在的理由）

绿=拿到锁/成功，黄=等待，红=冲突/拒绝，蓝=校验。

TA · 接受 A→B
t0 BEGIN 事务
t1 预读请求 R1（A→B pending）
t2 锁请求行 R1 FOR UPDATE → 仍 pending ✅
t3 block 双向查 → 无 ✅（还没看到 TB 的黑名单）
t4 COUNT 双方好友数 ✅
t5 INSERT 双向好友边 (A,B)(B,A) —— 黑名单已存在，边照插 ✗
t6 COMMIT ✗
TB · B 拉黑 A
BEGIN 事务
预读（决定拉黑 A）
插 blocks (B,A) ✅
DELETE friendships 双向（此刻没边，删空）✅
UPDATE 两人间 pending 请求 → rejected ✅
COMMIT ✅
（结束）
结果（无 pair 守卫）：B 的黑名单里有 A，friendships 里又有 A↔B —— 既好友又拉黑，违反不变量。
加 pair 守卫后：TA、TB 抢 pair(A,B) 同一行守卫，全序执行 —— 先 TB 则 TA 复核时看到黑名单/请求已 rejected 而放弃；先 TA 则 TB 删掉边。不会再出现「边在黑名单之后插入」的交错。
