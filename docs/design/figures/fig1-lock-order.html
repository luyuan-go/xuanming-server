AcceptRequest 锁序示意（单事务内，按 1→7 顺序拿锁）

锁的载体是【行】，不是玩家。所有锁持有到 COMMIT 才统一释放。

① 预读
读请求行不加锁，只为拿到 requester/target —— 因为 pair 守卫的 key 需要这对玩家 ID
② pair 守卫
friend_pair_guards(lo,hi) 加排他锁 —— 同一对玩家的 Accept / Block / AddFriend 在此全串行，一个做完另一个才进
③ player 守卫
maxFriends>0 时按 player_id 升序锁两个 friend_player_guards —— 好友上限 COUNT 在此域内才权威
④ 请求行
friend_requests FOR UPDATE 锁请求行，复核仍 pending；被并发处理（Block/另一次 accept）则本次放弃
⑤ block 校验
blocks FOR UPDATE 双向查黑名单（锁定读，防 TOCTOU）
⑥ COUNT 上限
守卫锁内 COUNT friendships FOR UPDATE，对双方各查一次好友数是否超限
⑦ 写 + 提交
UPDATE 置 accepted + 双向 INSERT IGNORE 建边 + 反向 pending 收敛 → COMMIT 释放全部锁。要么全成、要么全回滚

锁序纪律：pair 守卫 → player 守卫（升序）→ 业务行。单事务最多持一把 pair 守卫，player 守卫恒按升序取 —— 这是防死锁的关键。
