一进事务，按顺序拿三把锁（锁序：pair → player 升序 → 业务行）

三者缺一不可：pair 管「这一对关系不乱」，player 管「这个人限额不超」，业务行锁管「这一行不被并发改」

第 1 把 · pair 守卫
friend_pair_guards
(lo,hi) = (50,100)
锁 AB 这一对。
防：同对的 Accept / Block / AddFriend 互相矛盾 —— 既好友又拉黑、已拉黑+pending
第 2 把 · player 守卫（升序）
friend_player_guards
(A) → (B)
锁 A 和 B 各自。
防：A/B 的好友数上限被并发穿透（必须按 ID 升序取，防死锁）
第 3 把 · 业务行锁
friend_requests
WHERE request_id=?
FOR UPDATE
锁 那条请求行。
防：同一请求被并发 accept / reject / Block 改状态 → 复核仍 pending 才动手
全部拿到 → 做校验 + 写（置 accepted、插两条双向边、收敛反向 pending）→ COMMIT 三把锁一起放。锁的是「行」，A、B 两个玩家没有被整体锁住，锁住的是这三行数据。
